# Intra Meta 🏴 Evaluationのフラグについて

> [!note]
> 💡 このページには、Evaluationで使用するフラグの仕様・詳細について書いてあります。

## フラグについて

### 1. 概要

フラグとは、Evaluationを行う際に使用する、ページ下部にある**Ratings**の各項目のことを指します。

どのようなレビューが行われたのかを、レビュワー・レビュイー・42の全体に共有するために存在します。

Evaluationで使用するフラグのイメージ図

### 2. 仕様

フラグをいずれか1つ選ばない限り、Evaluationは終了できない仕様になっています。

レビュワーは、そのレビューで感じたものに最も近いフラグを選択します。選択したフラグは後から訂正できないため、押し間違いのないように確認してください。

トラブルを避けるために、そのフラグを選択した意図や理由をレビュイーに説明すると良いでしょう。

### 3. リスクについて

フラグは、あくまでレビューの質を担保するためのガイドラインとして存在します。

レビューにおいて懸念されるリスクとしては、フラグが形骸化してしまうことです。

くれぐれもフラグ対策を目標として課題を提出をしたり、フラグを超えることを目標にすることは行わないようにしましょう。これは学習において、意味をなさない行為です。

## フラグの各項目内容

以下は、フラグの各項目の説明内容です。

| Flag | Description |
|---|---|
| Ok | デフォルト |
| Empty work | 提出先に何も提出されていない |
| No author file | author fileがない |
| Invalid compliation | コンパイルできない、コンパイルエラー、makeルールのエラー |
| Norme | NorminetteがWarningやエラーを出力した(Warningに関しては.cファイルや.hファイルの時のみエラーとして含みます)、normのPDFにそぐわない内容など |
| Cheat | 提出されたコードが他人のコードのコピー&ペーストなど |
| Can’t support / explain code | 提出されたコードを充分に説明できない |
| Crash | Segfault, Infinite loop |
| Incomplete group | グループ課題でレビュイーの人数が足りない |
| Outstanding project | 他の人たちに共有したいプロジェクトだった |
| Leaks | メモリリークを検知した |
| Forbidden function | 禁止されている関数を使用した |

### 2. コピー&ペースト・丸写しをしたコードの提出についての補足

コピー&ペースト・丸写しをしたコードの提出を、42 Tokyoは推奨しません。

理解・説明をするスキルに加え、実装を行うスキルの会得を念頭に42 Tokyoは運営されています。

コピーされたコードからは、技術的なスキルを証明することができないため、このような行為を不正行為と判断する場合があります。

なお、この見解は42 Tokyoにおける限定的なルールであるため、実社会におけるあらゆる手段・可能性に対する言及ではありません。

課題によっては、コピーされたコードの提出がチート行為として検知され、問題となる可能性があります。

チート行為として判断された際に、一方的にチートを通告し、スコアが即座に-42点へ減点される・処分されることはありません。

チーム開発したメンバーの一人ひとりと面談を行い、重要なコンセプトの説明や、あるコンセプトの実装等を行ってもらいます。

## 学生相談窓口の案内 (トラブルの解決・通報)

Ok以外のフラグを使用することに心理的なハードルがある学生もいるかもしれません。

無難なフラグを選択し、ことなきを得ることは楽な方法です。しかし、レビューを行うことの意義・本質から逸脱した行動であることを忘れないようにしてください。

また、自分自身が適切だと考えるフラグを、相手が受け入れてくれないこともあるかもしれません。そのような状況で、話し合い解決することもレビューのうちです。P2P学習を向上させるために、議論を重ねましょう。

しかし、学生同士の間でどうしても解決しない場合や、不正を見かけた・聞いた場合は、以下の学生個別相談窓口から運営事務局に連絡してください。
